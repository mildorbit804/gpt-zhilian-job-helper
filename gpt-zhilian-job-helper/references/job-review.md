# 六项核查与交付

这六项是助手在筛选中执行的核查方法，不是六条默认排除规则。使用者的接受标准来自其明确要求；已有答案沿用，不增加一套必答问卷。只使用已授权取得的背景与页面证据。

## 1. 岗位详情：薪资结构

分别记录招聘薪资区间、固定底薪、绩效、提成或分成、奖金与补贴；只写页面能确认的数额和条件。保留月薪/年薪、币种、税前/税后及试用期差异；没写的标未说明，不推算到手工资。综合薪资和最高收入不能作为固定底薪，绩效/补贴是否有条件也不能猜。

同时查看正文及可见福利、技能标签。不同来源不一致时列原文和来源，不用较高的一项覆盖较低的一项。只有使用者已明确不接受某种结构或设定了金额要求，才按其规则排除；未设要求时说明结构和未核信息，不因有提成就淘汰。薪资区间跨度阈值由使用者决定，不设置默认比例。

salary_min/salary_max 只存明确标明口径的招聘薪资上下限，不能偷偷改成底薪或稳定收入。固定收入与浮动收入的复合判断走已授权的 manual 规则；未支持的新字段不塞进 facts。原始薪资和结构说明另存本轮核查汇总。

## 2. 阅读职责：名称与实际工作

从 JD 的具体任务、考核目标、可见技能标签提炼一到两个主要职责，再和使用者目标对照。例如名称为助理、职责却以客户开发和销售指标为主，应说明实际工作内容；不只凭名称归类。主要任务与偶尔协助分开，职责没有占比时不编百分比。

标题与内容不同本身不证明欺诈，也不是自动排除理由。按使用者已确认的职责偏好处理；没有对应要求时只说明。若现有规则只筛标题，它仍只筛标题，不能擅自扩大为正文或公司名。需要按实际职责筛选时，应将用户已经提出的职责要求记录为带来源的 manual 规则，不增加用户没有要求的排除条件。

## 3. 对照背景：资格差距

逐项比较学历、专业、对口经验、技能、证书等与当前岗位相关的条件。每项记录：岗位原文、要求强度（必须/一般要求/优先或加分）、已授权背景依据、符合/不符合/信息不足。普通要求不自动升级为不可协商门槛；“优先”不能直接当硬性不符。

同一要求重复表达只计一次；“本科”和“本科学历”不算两项。未知学历、没有提供年限、不明确是否持证，均是信息不足，不算已知不符。不要从学校或专业猜学历，不把总工作年限当对口年限，不把参加培训当取得证书。

只有使用者选择了“达到多少项不符就提醒/排除”等策略，才按确认的计数范围和阈值处理，具体见经验包末尾的附加策略。明确不可缺少的资格单列，即使采用数量策略也不能用其他优点掩盖；没有证据时说明待核，不声称具备。

资料足够直接比较。缺资料实质影响筛选时只补问必要项，解释用于核对哪项岗位要求；不主动读取个人资料，也不把筛选核对变成所有人必填学历问卷。招呼语中的应届生/实习生学历询问仍按既有流程。

## 4. 判断规则：措辞与上下文

作息、加班、压力、销售、公司性质等判断都读完整短句及必要上下文，分清肯定、否定、条件、例子和描述对象：

- “无需加班”不算要求加班；“不强制加班，但忙时需要加班”应拆开说明，不能只抓一个词。
- “单双休/大小周”不能因为包含“双休”就当双休。
- “有一定抗压能力”的概括性要求与明确高压、持续超负荷描述分开；是否排除按使用者标准。
- “为某类企业提供服务”描述客户，不能直接证明招聘公司属于该行业或性质。

读取与解释上下文是助手的必要工作，不要求使用者选择是否防止误判。关键词屏蔽仍按用户确认的字面匹配执行，不在这一步暗改其范围。

程序的 contains_any 等是字面匹配，不等于语义理解；涉及否定、必须/优先、主体关系或多个条件的要求，优先用 manual 表达用户的既定意思。发现字面规则误判时保留证据，修正同一要求的表达并重算，不在最终报告里偷偷反转程序结论。经验包中已有自动规则若解析与原文冲突，记录解析缺陷，不改原文、不报“全部核查通过”；需要修复解析或用等效的 manual 规则承接原授权，重新取得一致结果。

## 5. 查询公司：资料相互核对

对照公司简介中的主营/兼营业务、已读在招职位、平台工商字段和行业标签，给出一句易懂的公司业务介绍。每个结论说明是平台陈述还是综合资料的判断；只有推测就标明，不当成确认事实。

行业标签可能是企业自行填写，经营范围只说明登记内容，不证明当前实际经营；招某类岗位也不足以证明主业。品牌、招聘主体、登记主体存在差异时保留名称和关系不明之处，不直接合并。资料互相矛盾、缺少介绍或有 AI 生成提示时，应补核或列出未核事项，不直接称为空壳或骗子。

不新设“行业不喜欢”或“公司有疑点就排除”规则。已有介绍不足、资本、地址、招聘结构经验继续按各自授权执行；该方法补充证据和说明，不重复增加经验项。

## 6. 去重与交付：相似岗位差异

先遵守当前身份匹配与已投去重规则。确定同公司同岗位的，只留一条；明确已投、拒绝、被现行规则排除的记录不重新推荐，重发提醒仍按其专门流程。

对同一已确认公司、标题相近但身份不同且均在本轮正常结果中的岗位，比较已读职责、薪资口径、地点、经验要求与招聘人（仅岗位页可见信息，不读消息）。列出主要差异、各自来源和链接；缺一方资料就写无法确认，不能把未读部分说成相同。标题相近或薪资相同不能单独证明重复，标题变动也不能证明重新发布。

差异说明由助手在核查汇总中整理，程序没有自动产出相似岗位差异表的命令；不虚构接口，不更改原始身份或清空历史记录来放行。已被程序按确定身份合并的记录不强行拆成多个候选；若身份判断确有冲突，标需核实并修正实际匹配问题后重算，不能越过去重。

## 保存与交付

在使用者的本轮目录保存一份核查汇总，以岗位 ID 或已有 key 对应原条目，包含：
- 薪资原文、结构和未说明项；
- 实际主责及与目标的关系；
- 有证据的资格差距、未知项与适用策略；
- 影响判断的关键上下文；
- 公司业务说明、来源与冲突；
- 仅在需要时列出的相似岗位差异。

这些说明不是程序新增字段。已确认的筛选要求用既有 config rules/manual 与 local review 接入，按 [配置格式](config-schema.md) 和 [输入格式](observations.md) 保存；程序不支持的说明保留在汇总，不能伪造事实或接口。个人背景只保留本次判断必要的摘要和来源指引，不复制整份简历或无关个人资料。

候选交付先重算最新结果，再完成六项核查；程序的 reviewRequired 仍需助手处理。未查完写未查完，已排除说明原因。按实际相关程度展示，不把每个岗位报告扩成六张空表；合适岗位仍配对应链接与招呼语。六项核查不额外联系招聘方、不访问消息、不扩大为全站搜索。
